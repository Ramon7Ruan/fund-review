# 如何新增一个功能

给组员看的操作指南。全程**不需要修改任何已存在的文件**。

---

## 准备

```bash
git checkout main && git pull
git checkout -b feat/你的功能名
make setup          # 第一次需要，装依赖
```

## 第一步：复制示例

```bash
cp -R engine/plugins/momentum_summary       engine/plugins/你的功能名
cp -R web/src/features/momentum-summary     web/src/features/你的功能名
```

目录名用小写短横线或下划线，不要与已有的重名。

## 第二步：改三处名字

后端 `engine/plugins/你的功能名/plugin.py`：

```python
PLUGIN = AlgorithmPlugin(
    id="模块.你的功能名",        # 必须唯一，点分小写
    title="卡片上显示的名字",
    ...
)
```

前端 `web/src/features/你的功能名/manifest.ts`：

```ts
const manifest: FeatureManifest = {
  id: "模块.你的功能名",   // 必须与后端 PLUGIN.id 完全一致
  title: "卡片上显示的名字",
  order: 60,              // 数字小的排在前面
  span: 1,                // 1 = 单列，2 = 双列
};
```

## 第三步：写算法

只改 `plugin.py` 里的 `run(ctx)` 函数体。

```python
def run(ctx: PluginContext) -> PluginResult:
    raw = ctx.data.get("nav_series") or []
    # 在这里写你的算法
    return PluginResult(status="ready", data=dict(your_key="your_value"))
```

规则：

- `ctx.data` 里有 `nav_series`、`holdings`、`quotes`、`benchmark_returns`，没有的数据自己判断为空。
- `data` 里放能 JSON 序列化的东西（数字、字符串、列表、字典）。
- **不要**发起网络请求，**不要**读写数据库，**不要**修改 `ctx` 里的任何东西。
- 算不出来就抛 `ValueError`，前端会显示"执行失败"而不会崩。

## 第四步：改卡片

只改 `Panel.tsx`。

```tsx
export default function Panel({ result }: PanelProps) {
  const data = result?.data ?? {};
  return (
    <div className="card">
      <h3 className="text-sm font-semibold">你的标题</h3>
      <p className="mt-2 text-xs">{(data as { your_key?: string }).your_key}</p>
    </div>
  );
}
```

`Panel` 只会在 `status === "ready"` 时被调用，不用处理加载失败。

## 第五步：自测

```bash
make check                       # 全部测试与构建
python -m pytest tests -k 你的   # 只跑自己的测试（可选）
```

浏览器打开 http://localhost:5173 ，输入基金代码，你的卡片应该出现在下面。
如果没出现，去看 http://localhost:5173/plugins ，那里会列出后端实际加载到的插件和失败原因。

## 第六步：提 PR

```bash
git add -A
git commit -m "feat(你的模块): 一句话说明"
git push -u origin feat/你的功能名
```

PR 里写清：改了什么、`Closes #N`、`make check` 通过的截图。

---

## 常见问题

**卡片没出现**

1. 检查 `manifest.ts` 的 `id` 与 `plugin.py` 的 `PLUGIN.id` 是否完全一致（大小写、点、下划线）。
2. 打开 `/plugins` 页看后端是否加载到了你目录，失败原因会写在那里。
3. 目录下必须有 `plugin.py` 和 `manifest.ts`，文件名不能改。

**后端启动日志里有 failed**

说明 `plugin.py` 导入时就报错了，通常是语法错误或 import 了不存在的模块。先把文件单独跑一遍：`python -c "import engine.plugins.你的功能名.plugin"`。

**测试红了**

先看是本模块的测试还是别人的。别人的测试红了说明你改到了公共文件，检查 `git status`，恢复它。

**需要新的数据**

不要自己抓。到 issue 里提"数据接入"需求，由数据层的负责人加进 `data_pipeline/sources/`，然后通过 `ctx.data` 提供给你。
