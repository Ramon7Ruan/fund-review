## 二、验收标准（对齐 Issue #2 与用户要求）

| 验收 | 本计划如何达成 |
|---|---|
| 分项之和 = 实际收益，残差 < 0.1% | 期初权重 × 个股收益 + 显式残差，真实 fixtures 对账 |
| 对账测试自动化 | `tests/test_attribution.py`，CI 必过 |
| 至少一种归因口径 | 贡献度 + 行业拆解；行业部分/个股超额两项拆分 |
| 同输入两次结果一致 | 固定排序 + 无时间/随机依赖，重复运行相等测试 |
| 事件准确、宁缺毋滥 | 四条准入门槛 + 过滤测试（无关、无链接、无日期一律丢弃） |
| 不做因果、不给意见 | 禁用词扫描测试；事件不参与任何计算 |

## 三、设计决策

### 3.1 归因口径：两层拆解，不做标准 Brinson 三项

标准 Brinson 的「行业配置」需要基准组合行业权重，当前没有这项数据。**没有基准权重硬算配置项等于编数字**，所以：

- v0.3 交付：贡献度、行业汇总、行业部分/个股超额两项拆分、显式残差。
- Brinson 三项列入后续，前置条件是接入基准行业权重数据。

### 3.2 事件源：先探针，不可用就不上网抓

事件准确性是用户第一要求，因此**数据源可行性先于功能实现**：

1. 先用探针验证公告类接口能否稳定给出「日期 + 标题 + 原文链接 + 证券代码」四要素。
2. 四要素不全、链接不可达、字段不稳定的源，**直接弃用**。
3. 所有源都不可用时，事件模块交付「契约 + 过滤 + 空状态」，走本地导入，不降级为不可靠抓取。

### 3.3 拆 PR

Issue #2 规模为 L。建议三个 PR，各自独立可验收：

| PR | 内容 | 依赖 |
|---|---|---|
| PR-A | 数据接入扩展（个股行情、行业映射、行业指数收益进 ctx.data） | 无 |
| PR-B | 归因核心 + 插件 + 对账测试 | PR-A |
| PR-C | 事件陈列（来源、过滤、空状态、文案约束） | PR-B |

## 四、任务拆分

### T0：口径确认与数据源探针

- 确认 `归因口径.md`，重点是两层拆解与事件四条准入门槛。
- 扩展 `scripts/probe_sources.py`：验证个股行情是否含复权标识、行业指数可抓区间、公告源四要素是否齐全。
- 产出探针结论：每个源「可用 / 不可用 + 原因」。
- **核验**：探针真实跑一遍，结论落盘；事件源不可用则记录并走 3.2 第 3 条。

### T1：数据接入扩展（PR-A）

- `DataService` 新增 `get_quotes(codes, month)`、`get_industry_map(codes)`、`get_industry_returns(month)`。
- 沿用既有优先级「缓存 → 主源 → 备源 → 导入 → 报错」，来源写入 `meta`。
- 在契约第 5 节把 `quotes` / `industry_map` / `benchmark_returns` 状态改为已提供。
- **核验**：单测 + 真实调用，断言 `ctx.data` 三个键有值、字段符合 `DailyBar` 口径、行业只填申万一级。

### T2：归因核心（PR-B）

- `compute_contributions` 扩展：行业汇总、`total_contribution`、`residual_return`。
- 权重漂移接入：披露权重 → 区间期初权重；数据不足时降级并在 `notes` 披露。
- 输出统一走 `AttributionResult`，`round(x, 8)`，排序固定。
- **核验**：对账测试（容差 0.001）、缺失行情进残差、行业未映射归「未映射」、两次运行结果一致。

### T3：行业部分 / 个股超额拆分（PR-B）

- 按口径 2.4 第二层拆分，两项之和必须等于 `c_i`。
- 行业指数缺失时该层 `stub`，第一层照常返回。
- **核验**：拆分恒等式测试 + 行业数据缺失降级测试。

### T4：插件与接口接入（PR-B）

- `attribution.brinson` 由 stub 转 ready，数据不足时回退 stub 并写明原因。
- `api/routes/review.py` 把新数据键放进 `ctx.data`，归因结果进 `results`。
- **核验**：起服务真实调用 `/api/review`，110022 / 2026-10 返回归因分区，残差 < 0.001，其余分区不受影响。

### T5：事件陈列（PR-C）

- 事件源抓取 + 归一化为 `{date, title, url, source, related_code, event_type}`。
- 四条准入门槛过滤 + 去重 + 丢弃计数写 `notes`。
- 文案禁用词约束、日期倒序、空状态固定文案；契约登记 `events` 扩展字段。
- **核验**：构造「无关事件、无链接、无日期、重复事件」样本，断言全部被过滤；禁用词扫描通过；无事件时返回空状态文案而非空列表之外的内容。

### T6：总体真实验收

- 全量测试 + ruff + 前端测试与构建。
- 真实端到端：三只样本基金分别跑 `/api/review`，检查对账、事件关联对象确为披露持仓、无因果表述。
- 同一请求连续调用两次，结果一致。
- **核验**：以上全绿后才合并，Issue #2 评论更新验收对照。

### T7：文档同步

- 更新数据口径总表（归因公式、事件字段）、契约键状态、README 进度。

## 五、风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 公告源字段不全或不稳定 | 事件无法保证可溯源 | T0 探针先验；不可用则只做导入与空状态 |
| 个股行情不复权 | 除权月份个股贡献失真 | `meta` 标注复权方式，`notes` 披露，差额进残差 |
| 持仓披露期与回顾月错位 | 权重不准 | 漂移处理；数据不足时降级并披露，不假装精确 |
| 前十大持仓覆盖率低 | 残差偏大 | 残差显式展示，禁止摊薄到已知项 |
| 基准行业权重缺失 | 无法做 Brinson 配置项 | v0.3 不做，列入后续 |
| 多数据源抓取耗时 | 接口变慢 | 复用缓存与降级；个股行情按持仓代码批量取 |
