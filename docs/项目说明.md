# fund-review 项目说明

> 这份文件说明**项目做什么、做到什么程度、系统怎么搭**。
> 协作流程、分支规范、任务卡写法见 [`小组协作手册.md`](./小组协作手册.md)，本文不重复。

## 一、项目定位

面向个人投资者的**基金投后月度回顾工具**。

用户输入一只基金代码和一个月份，系统回答三个问题：

1. 这个月基金的涨跌，主要是哪些持仓资产贡献的？
2. 这些资产中，异动的个股属于哪些行业，行业整体表现如何？
3. 异动发生的前后，市场上出现了哪些公告、新闻和政策信息？

**工程目标：支持现场输入任意基金代码实时计算**，不是只能演示预置样例。

## 二、功能范围

### 2.1 做什么

| 层 | 功能 | 输出 |
|---|---|---|
| 数据接入 | 输入基金代码，抓取基金净值、最近一期持仓、个股行情、行业指数 | 净值曲线、持仓结构表 |
| L1 资产贡献 | 按权重漂移推算月内持仓权重，计算各持仓对基金月度收益的贡献 | 贡献度瀑布图、贡献明细表 |
| L2 行业拆解 | 个股映射到申万一级行业，汇总行业贡献，对照行业指数表现 | 行业贡献条形图、行业超额对照 |
| L3 异动呈现 | 检测本月异动持仓，抓取同一时间窗口的公告与新闻 | 异动卡片：量化描述 + 原文链接 + 观察角度提示 |
| 报告导出 | 汇总上述内容生成月度回顾报告 | 可导出的月度报告 |

### 2.2 不做什么

这一节和上一节同等重要，开发前请先读。

- **不做因果归因**。系统不输出"本月下跌由某法规导致"这类结论，只把异动和同时期的公开信息摆出来，判断留给用户。
- **不使用 LLM 做事件解读**。L3 是信息检索与呈现，不是文本生成。
- **不承诺个券级债券归因**。债券个券估值与成交数据无公开稳定来源，债券部分用指数近似并明确标注。
- **不承诺全持仓精确归因**。公募基金季报只披露前十大重仓，未披露部分以"其他股票"残差项显式列出，不摊进已知持仓。
- **不做投资建议、不做组合推荐、不做交易功能**。

### 2.3 界面上的呈现原则

- 所有数字必须可追溯到计算过程，所有事件必须可点回原文链接。
- 推算得到的数值（如月内权重）与直接抓取的数据，在界面上区分开标注。
- 某条异动没抓到相关新闻时，卡片仍显示量化描述，**不空白、不报错**。

## 三、系统架构

```
┌─────────────────────────────────────────────────┐
│ web/        React + TypeScript + ECharts        │
│             净值曲线 / 贡献瀑布 / 行业图 / 异动卡 │
└────────────────────┬────────────────────────────┘
                     │ HTTP（OpenAPI 契约）
┌────────────────────▼────────────────────────────┐
│ api/        FastAPI，只读接口                    │
│             基金信息 / 月度回顾 / 异动清单 / 导出 │
└────────────────────┬────────────────────────────┘
                     │
┌────────────────────▼────────────────────────────┐
│ engine/     纯函数计算内核（不碰网络、不碰数据库）│
│             权重漂移 · 贡献度 · 行业拆解 · 异动检测│
└────────────────────┬────────────────────────────┘
                     │ 只读取标准化后的数据
┌────────────────────▼────────────────────────────┐
│ data_pipeline/  抓取、清洗、备用源切换、缓存写入   │
│                 akshare 为主，每类数据至少两个源  │
└────────────────────┬────────────────────────────┘
                     │
┌────────────────────▼────────────────────────────┐
│ data_pipeline/cache/   SQLite 缓存（已实现）      │
│                        parquet 行情存储（预留）   │
└─────────────────────────────────────────────────┘
```

### 分层职责与边界

| 目录 | 职责 | 不允许做 |
|---|---|---|
| `data_pipeline/` | 对外抓取、字段标准化、备用源切换、缓存读写 | 不做任何收益或归因计算 |
| `engine/` | 权重漂移、贡献度、行业拆解、异动检测 | 不发起网络请求、不读写数据库，输入输出都是数据结构 |
| `api/` | 编排 pipeline 与 engine，对外暴露接口 | 不写业务算法 |
| `web/` | 展示与交互、参数输入、报告预览 | 不实现计算逻辑 |
| `report/` | 把月度回顾结果渲染为可导出文件（v0.3 实现，尚未建目录） | 不重新计算 |

**`engine/` 必须是纯函数**，这是全组对账测试能跑起来的前提。归因算法的正确性只在 `engine/` 验证，其他层不重复实现。

### 技术栈

| 层 | 选型 | 理由 |
|---|---|---|
| 数据抓取与清洗 | Python + `akshare` + `pandas` | 基金与行情数据唯一有现成生态的一侧 |
| 计算内核 | `numpy` / `pandas` | 贡献度与行业拆解为加权算术，配合对账测试 |
| 接口 | FastAPI | 自动生成 OpenAPI，前后端不必口头约定字段 |
| 存储 | SQLite + parquet | 本地零运维，组员不用配数据库 |
| 前端 | React + TypeScript + ECharts | 瀑布图、行业图、时间轴都有现成组件 |
| 测试 | pytest（对账）+ vitest（前端） | 两套测试，职责分开 |

选型的决定因素是**数据抓取与清洗都在后端**，不是算法复杂度。本项目的数据规模（月度 × 几十只持仓 × 几千个净值点）在任何语言里都是毫秒级，性能不构成选型依据。

## 四、一次月度回顾的完整流程

1. 用户输入基金代码与目标月份。
2. `data_pipeline` 抓取基金净值序列与最近一期披露持仓，写入缓存。
3. `engine` 以披露持仓为起点，按 buy-and-hold 方式推算月内权重漂移。
4. `data_pipeline` 抓取持仓个股行情与申万行业指数。
5. `engine` 计算个股贡献度与行业贡献，并执行对账：分项之和应等于组合实际收益，残差单独列出。
6. `engine` 按异动规则筛选本月异动持仓。
7. `data_pipeline` **只对筛出的异动标的**抓取对应时间窗口的公告与新闻。
8. `api` 汇总为结构化结果返回，`web` 渲染页面并支持导出报告。

### 为什么先检测异动再抓事件

对全部持仓抓全月新闻，抓取量和噪音都会失控。先量化筛选，通常每月只剩个位数异动标的，事件抓取量随之降到可控范围。

同时，**异动清单本身就是月度回顾的主体内容**：即使某条没有抓到相关报道，量化描述依然成立。

### 异动判定规则（初值，可调）

| 类型 | 触发条件 |
|---|---|
| 价格异动 | 单日涨跌幅绝对值 ≥ 5%，或触及涨跌停 |
| 量能异动 | 当日成交额 ≥ 20 日均值的 2 倍 |
| 相对异动 | 个股当日涨跌 − 所属行业指数当日涨跌 ≥ 4% |
| 行业异动 | 申万一级行业指数当日涨跌排名前 3 或后 3 |

阈值集中在配置文件中管理，不散落在代码里。

### 异动卡片提供的观察角度

程序只给模板化提示，不给结论：

- 当日是否发布公告，公告类型是什么
- 所属行业当日在全部行业中的涨跌排名
- 当日成交额相对近期是否明显放大
- 同一时间窗口内是否有相关政策或产业新闻

## 五、实时计算模式设计

支持任意基金代码实时计算，需要额外处理三件事。

### 5.1 缓存策略

| 数据类型 | 缓存有效期 | 说明 |
|---|---|---|
| 基金净值、个股行情、行业指数 | 当日有效 | 收盘后数据不再变化 |
| 基金持仓 | 按季度长期有效 | 披露频率低，可长期复用 |
| 公告与新闻 | 长期有效 | 历史事件不会改写 |

首次计算一只基金需要多次抓取，耗时明显长于后续查询，接口必须提供加载状态，不能让页面无响应。

### 5.2 抓取纪律

- 串行抓取并限速，避免触发数据源风控。
- 每个请求设置超时，单源失败立即切备用源，不反复重试同一源。
- 抓取结果先落盘再计算，计算失败不会导致重新抓取。

### 5.3 降级顺序

```
主数据源 → 备用数据源 → 本地缓存 → 明确提示该部分数据缺失
```

任何一级失败都不允许让整页报错或空白。

## 六、数据来源与实测情况

以下为本机实测结果（2026-11-15，akshare 1.18.94），不是文档推断。

| 数据 | 接口 | 实测 |
|---|---|---|
| 基金单位净值 | `fund_open_fund_info_em` | 正常，净值更新至最新交易日 |
| 基金持仓（占净值比例、持股数、持仓市值） | `fund_portfolio_hold_em` | 正常，按季度返回 |
| 申万一级行业列表 | `index_first_info_sw` | 备份提供行业代码；个股行业映射另有本地快照 |
| 申万行业指数日线 | `index_hist_sw` | 在线失败时使用同月收盘价快照 |
| 个股日线（新浪） | `stock_zh_a_daily` | 正常，含成交额与换手率 |
| 个股日线（腾讯） | `stock_zh_a_hist_tx` | 正常，可作互备 |
| 东方财富行情接口 | `stock_zh_a_hist`、`stock_zh_a_spot_em` | **本机连接失败**，需备用源 |

东财接口失败为本机网络环境所致，但它说明一条必须遵守的规则：**每类数据至少两个可用来源，不允许写死单一接口**。

公告与新闻源（巨潮资讯、财联社等）首页可达，具体列表接口的稳定性与反爬策略在 `#1 数据接入` 阶段实测后补充到本节。

## 七、已知数据约束与应对

| 约束 | 影响 | 应对 |
|---|---|---|
| 基金持仓仅季报披露前十大 | 月度权重为推算值，存在未披露部分 | 显式列出"其他股票"残差项，报告中注明推算口径 |
| 债券个券估值无公开数据 | 债券无法做到个券级拆解 | 用中债系列指数近似并标注 |
| 新闻与公告源可能反爬或变动 | L3 偶发抓不到内容 | 结果缓存；抓不到时只显示量化异动，不空白 |
| 演示现场网络不可用 | 实时计算无法进行 | 预置若干基金的完整缓存作为兜底，演示可切换至缓存模式 |

## 八、质量红线

1. **对账必须通过**：贡献度分项之和与组合实际收益的残差 < 0.1%，残差项单独披露。对账不通过的算法不合并。
2. **数据源必须有备份**：任何单一接口失效都不能让功能整体不可用。
3. **抓取结果必须可复现**：同一份缓存数据，计算结果必须完全一致。
4. **计算与信息呈现必须分开**：页面上推算值、抓取值、原始信息三者的来源标注清楚。
