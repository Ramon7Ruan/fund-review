> 本文是 [`数据口径与契约.md`](./数据口径与契约.md) 在归因模块的细化，单位、日期、精度等全局约定以那份文件为准，本文不重复定义。

## 0. 一句话边界

**归因引擎只做两件事：把收益拆成可对账的数字，把可核验的相关事件摆在一起。**
**它不做因果判断，不给任何投资意见。**

页面与接口必须固定带一句提示：

> 以下内容为数据拆解与公开事件整理。事件与涨跌同时出现只代表时间上的相关性，不代表因果关系，不构成投资建议。

---

## 1. 归因范围：做什么、不做什么

| 做 | 不做 |
|---|---|
| 把区间收益拆到持仓、行业，分项之和可对账 | 断言"某事件导致某次涨跌" |
| 标注每部分数据的来源、披露期、假设 | 预测收益、评价基金经理能力 |
| 陈列与基金/持仓**直接相关**且**可溯源**的公开事件 | 给买卖建议、给事件打"利好/利空"标签 |
| 数据不足时明确说"无法拆解"，残差显式披露 | 用推测、语义联想补齐拆不出来的部分 |

**宁可少展示，不可错展示。** 任何无法核验来源或无法确认关联的内容，一律不进入结果。

## 2. 数值归因口径

### 2.1 输入来源

插件只从 `ctx.data` 取数，**禁止自行抓取**。涉及键：

| 键 | 用途 | 当前状态 |
|---|---|---|
| `nav_total_return` | 基金区间收益（复权，与 #4 完全一致） | 已提供 |
| `holdings` | 披露持仓与权重 | 已提供 |
| `quotes` | 个股日线，算个股区间收益 | 占位，需 #1 扩展 |
| `industry_map` | 个股 → 申万一级行业 | 占位，需 #1 扩展 |
| `benchmark_returns` | 申万一级行业指数区间收益 | 占位，需 #1 扩展 |

### 2.2 区间与收益

- 区间：自然月首末交易日，与收益计算一致。
- 基金收益 `R_fund`：复权总回报指数首末**比值**，直接复用 #4 结果，不另算一套。
- 个股收益 `r_i`：区间首末收盘价之比 − 1。
  - 数据源必须标明复权方式（`meta.quotes.adjust`）。
  - 若只能拿到不复权行情，必须在 `notes` 披露「个股未复权，除权除息会影响个股贡献」，**不许假装已复权**。

### 2.3 权重

- 贡献度一律用**区间期初权重**，这是能对账的前提。
- 持仓是季度披露、披露基准日常常不在区间首日：按契约「权重漂移默认启用」，用 buy-and-hold 把披露权重漂移至区间首日（复用 `compute_weight_drift`）。
- 漂移所需的区间前行情拿不到时，退化为披露权重，并在 `notes` 写明「权重为 YYYY 年 Qn 披露，未漂移」。**漂移失败不许静默。**

### 2.4 拆解公式

第一层：贡献度与行业汇总（必须交付）

```
c_i        = w_i × r_i                      单只持仓贡献
C_ind      = Σ_{i∈ind} c_i                  行业贡献
total      = Σ c_i
residual   = R_fund − total                 未披露持仓、债券、现金、费用等
对账：|total + residual − R_fund| < 0.001
```

第二层：行业部分与个股超额部分（建议交付）

```
c_i = w_i × r_ind + w_i × (r_i − r_ind)
      └ 行业部分 ┘   └ 个股超额部分 ┘
```

两项之和恒等于 `c_i`，所以**不破坏对账**。

**为什么 v0.3 不做标准 Brinson 三项**：行业配置项需要"基准组合的行业权重"（如沪深 300 行业权重），当前数据接入没有这项数据。没有基准权重就算配置项，等于编数字，违反本文第 0 条。三项拆解列为后续可选项，前提是先接入基准权重数据。

### 2.5 残差与缺失

| 情况 | 处理 |
|---|---|
| 某只个股行情缺失 | `period_return = null`，该持仓不进分项，差额留进 `residual` 并写 `notes` |
| 行业映射缺失 | `industry = ""`，归入「未映射」分组，**不猜行业** |
| 行业指数缺失 | 只交付第一层，第二层标 `stub` 并说明 |
| 前十大权重和 < 1 | 正常现象，差额即残差的主要来源，不许摊薄到已知项 |
| `residual_return` | 必须显式返回，即使为 0 |

### 2.6 精度与可复现

- 内部 float64 不截断，输出 `round(x, 8)`，前端 ×100 保留两位。
- 分项排序固定（贡献度升序，行业按名称），**同样的输入跑两次，结果逐字节一致**：不依赖当前时间、不依赖 dict 遍历顺序、不使用随机数。

## 3. 事件陈列口径（本次新增的核心约束）

### 3.1 事件字段

在契约登记的 `events` 键上扩展为：

```
{date, title, url, source, related_code, event_type}
```

`url` 为原文链接，`related_code` 为直接关联的基金或证券代码，`event_type` 取 `fund_notice` / `stock_notice` / `industry_policy`。

### 3.2 准入门槛：四条全部满足才展示

| 门槛 | 规则 | 不满足时 |
|---|---|---|
| 可溯源 | 有原文链接与来源名，链接指向公告原文 | 丢弃 |
| 直接相关 | `related_code` 等于本基金代码，或等于某只**披露持仓**的证券代码 | 丢弃 |
| 时间可确认 | 日期解析成功，且落在回顾区间或事件披露窗口内 | 丢弃 |
| 非重复 | 按 `source + title + date` 去重 | 合并 |

**明确禁止的关联方式**：按股票名称模糊匹配概念、按行业联想"相关政策"、把市场热点套到持仓上、由模型生成事件。

被丢弃的条数记入 `notes`（如「3 条来源不可核验，未展示」），让"少展示"本身可被检查。

### 3.3 展示规范

- 只陈列事实：日期、标题、来源、链接、关联对象。
- 按日期倒序，**不按"重要程度"或"影响大小"排序**，不标注正负面。
- 文案禁用词：`导致`、`因此`、`所以`、`利好`、`利空`、`建议`、`预计`、`有望`、`大概率`、`主力`、`抄底`、`跑赢`、`看好`。
- 事件**不参与收益计算、不进残差、不影响对账**，仅同页陈列。
- 空状态固定文案：「本期未检索到与持仓直接相关且可核验的公开事件」。**没有事件就显示这句，不许补内容。**

## 4. 验收标准

| 来源 | 验收 | 判定方式 |
|---|---|---|
| Issue #2 | 分项之和 = 组合实际收益，残差 < 0.001 | 真实 fixtures 自动化对账测试 |
| Issue #2 | 对账测试自动化，任何算法提交必过 | CI 中 `test_attribution*` 全绿 |
| Issue #2 | 至少支持一种归因口径 | 贡献度 + 行业拆解落地 |
| Issue #2 | 同输入两次结果一致 | 重复运行逐字段相等测试 |
| 用户要求 1 | 事件准确、宁可没有 | 每条事件四字段齐全；构造无关/无链接/无日期事件，必须被过滤 |
| 用户要求 2 | 不做因果、不给意见 | 输出文案禁用词扫描测试；事件不进入任何计算 |
