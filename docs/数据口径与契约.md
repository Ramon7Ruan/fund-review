# 数据口径与契约（Data Contract）

> 目的：**让不同分支的代码能拼在一起跑**。
> 这份文件是全项目唯一的数据口径来源。代码里的类型定义以 `engine/*/types.py` 为准，
> 本文解释"为什么这么定"以及"什么能改、什么不能改"。
>
> 只想知道字段和数值怎么写，直接查 [`数据口径总表.md`](./数据口径总表.md)（表格速查版）。
>
> 状态：已定稿（2026-11-18）　关联：#1 数据接入、#2 归因引擎、#4 收益计算

---

## 0. 这份文件解决什么问题

八个人并行开发时，最容易出的不是 bug，而是**口径漂移**：

- A 把权重写成 `9.74`，B 按 `0.0974` 算，结果差 100 倍
- A 的"月收益"用自然月首尾，B 用 30 天滚动
- A 在插件里自己抓数据，B 从 `ctx.data` 取，同一只基金两个数

所以本文件先把**单位、时点、精度、缺失处理**定死，再定每个字段的含义。

## 1. 三条总原则

| 原则 | 含义 |
|---|---|
| **一个字段只有一个权威定义** | 类型只写在 `engine/*/types.py`，插件里不许重复定义同义结构 |
| **缺失不隐藏** | 拿不到的数据用 `null` 并写明原因，不许用 0 或前值填充 |
| **计算只在 engine** | 抓取在 `data_pipeline`，展示在 `web`，插件只做纯函数变换 |

## 2. 全局约定

### 2.1 单位与精度

| 项 | 约定 | 示例 |
|---|---|---|
| 比例（权重、收益率、回撤、贡献度） | **小数**，不是百分数 | `0.0974` 表示 9.74% |
| 金额 | 人民币**元** | `184489.91` |
| 数量 | 股 / 份 | `118.19`（万股，沿用数据源口径并标注） |
| 内部计算 | 不截断，用 float64 | — |
| 存储 | 比例保留 8 位小数 | `round(x, 8)` |
| 前端展示 | 比例 × 100 后保留 2 位，加 `%` | `3.98%` |

**前端负责格式化，后端只给小数。** 后端不许返回 `"3.98%"` 这种字符串。

### 2.2 日期与时间

| 项 | 约定 |
|---|---|
| 交易日 | ISO 字符串 `YYYY-MM-DD` |
| 月份 | `YYYY-MM` |
| 时区 | Asia/Shanghai，不存 UTC 时间戳 |
| 月度区间 | 该自然月内**第一个交易日 → 最后一个交易日**，不是 30 天滚动 |
| 数据时点 | 每个数据集带 `as_of`（该数据截至哪一天） |

### 2.3 命名

- 字段一律 **snake_case 英文**：`period_return`、`start_nav`
- 中文只用于展示字段：`title`、`name`、`note`
- 插件 id：点分小写 `模块.功能`，如 `attribution.brinson`
- 同义字段禁止另起名字：已有 `weight` 就不许再写 `ratio`、`position_pct`

### 2.4 缺失与异常

| 情况 | 处理 |
|---|---|
| 字段拿不到 | `null` + 在 `notes` 说明 |
| 整个数据集拿不到 | 该分区标 `error`，**其他分区照常返回** |
| 计算结果对不上 | 写进 `residual_return` 并披露，不许摊进已知项 |
| 数值非法（负净值、权重 > 1） | 抛 `ValueError`，由接口层转为错误信息 |

## 3. 数据分层与流向

```
L0 原始层    akshare 返回的 DataFrame（不落地、不跨模块传递）
   ↓ data_pipeline/sources/*
L1 标准层    统一为 dict/list，字段、单位、日期格式已归一   ← 唯一事实源
   ↓ DataService（缓存 + 降级）
L2 计算层    engine 的纯函数，输入 L1，输出结果类型
   ↓ api/routes/review.py
L3 展示层    /api/review 的 JSON，前端只读不改
```

**规则：L1 之后不允许再出现 pandas DataFrame。** 所有跨模块数据都是 dict/list/dataclass。

### 3.1 数据源优先级（2026-11-18 定）

产品的核心用法是「输入基金代码就看到分析」，所以**抓取是主路径，本地导入是兜底**：

```
当日缓存 → 抓取主源 → 抓取备源 → 本地已导入数据 → 报错
```

- 每一级都在 `meta.source` 标明来源，页面上可追溯
- 回退到本地导入时，必须同时给出 `as_of`，让用户知道数据截至哪天
- **抓取失败不等于没有数据**：宁可标注「本地数据，截至 X 月 X 日」，也不要静默返回空
- 导入数据日常不参与主路径，只在容灾、演示离线、用户自持完整持仓时使用

## 4. 核心实体字典

### 4.1 FundInfo —— 基金基本信息

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `code` | str | 是 | 6 位数字 |
| `name` | str | 是 | 基金全称 |
| `type` | str | 否 | 混合型 / 股票型 / 债券型 |
| `company` | str | 否 | 基金公司 |
| `cached` | bool | 是 | 是否命中缓存（调试用） |

### 4.2 NavPoint —— 净值点

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `date` | str | 是 | `YYYY-MM-DD`，交易日 |
| `nav` | float | 是 | **单位净值**，> 0，永远保留原始值 |
| `dividend_per_share` | float | 否 | 除息日每份现金分红，无分红记 0 |
| `total_return_index` | float | 否 | 红利再投资总回报指数，**以数据源首日为 1**（通常是基金成立附近），不是月初归一化 |

**`nav` 永远是单位净值，不复权。** 复权只通过 `total_return_index` 体现，
计算区间收益时用后者。这条是硬约束：任何人不得改变 `nav` 的含义。

> 注意 `total_return_index` 的基准日：它是从数据源最早一天累计下来的，
> 所以任意一个月的首日值通常不是 1（例如 2026-10-08 是 2.761）。
> 区间收益请用首末**比值**，不要把它的绝对值当净值展示。

### 4.3 HoldingPosition —— 持仓

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `code` | str | 是 | 6 位证券代码 |
| `name` | str | 是 | 证券名称 |
| `weight` | float | 是 | 占净值比例，**小数**，∈ [0, 1] |
| `industry` | str | 否 | 申万一级行业名，空串表示未映射 |
| `period_return` | float \| null | 否 | 该区间内个股收益，小数 |
| `quarter` | str | 是 | 披露期，如 `2026年1季度股票投资明细` |

**权重之和要求**：`Σweight ≤ 1`，差额即未披露部分，用残差项呈现。

### 4.4 DailyBar —— 个股日线（待接入）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `date` | str | 是 | 交易日 |
| `open/high/low/close` | float | 是 | 价格，元 |
| `volume` | float | 是 | 成交量，股 |
| `amount` | float | 是 | 成交额，元（量能异动用这个，不用 volume） |
| `turnover` | float | 否 | 换手率，小数 |

### 4.5 ContributionItem / AttributionResult —— 归因结果

沿用 `engine/attribution/types.py`。关键约束：

```
Σ(items.contribution) + residual_return ≈ 组合区间收益
容差：0.001（0.1%）
```

`residual_return` 必须显式存在，即使为 0。

### 4.6 PortfolioReturn —— 组合收益（v0.2）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `month` | str | 是 | `YYYY-MM` |
| `total_return` | float | 是 | 组合区间收益，小数 |
| `contributions[]` | tuple | 是 | `{fund_code, weight, period_return, contribution}` |
| `cash_weight` | float | 是 | 现金权重，收益记 0 |
| `residual_return` | float | 是 | 未解释部分，即使为 0 也返回 |
| `notes[]` | tuple | 是 | 口径说明 |

**公式**：`R = Σ w_i × R_i + cash × 0 + residual`。

**边界**：权重和 ≤ 1；某基金无数据时记 0 并写 note；月内持仓变动用分段加权。

---

沿用 `engine/screening/types.py`。

- `kind` 只能是 `price` / `volume` / `relative` / `industry`
- `value` 为该规则的量纲：价格与相对用小数，量能为倍数，行业为名次
- **只描述事实，不解释原因**，`note` 里不许写"因为…所以…"

## 5. 插件上下文的键登记（最重要的一张表）

组员写插件时只从这里取数。**新增键必须先在本文登记**，否则别人的分支拿不到。

| 键 | 内容 | 类型 | 当前状态 |
|---|---|---|---|
| `nav_series` | 当月净值序列 | `list[{date, nav}]` | 已提供 |
| `nav_total_return` | 当月复权总回报指数 | `list[{date, total_return_index}]` | 已提供 |
| `portfolio` | 组合配置 | `list[{fund_code, weight}]` | 待接入（v0.2） |
| `nav_total_return_map` | 多基金复权序列 | `{code: [{date, total_return_index}]}` | 待接入（v0.2） |
| `holdings` | 最近一期持仓 | `list[HoldingPosition]` | 已提供 |
| `quotes` | 个股日线 `{code: [DailyBar]}` | dict | **占位，待 #1** |
| `benchmark_returns` | 行业基准收益 `{industry: r}` | dict | **占位，待 #1** |
| `industry_map` | 个股 → 行业 `{code: industry}` | dict | 待 #1 |
| `events` | 公告与新闻 `[{date, title, url, source}]` | list | 待 v0.3 |

插件取不到数据时的写法：

```python
raw = ctx.data.get("quotes") or {}
if not raw:
    return PluginResult.stub("等待 quotes 数据接入")
```

**不要**在插件里自行抓取，也不要假设键一定存在。

## 6. 接口契约

### POST /api/review

请求：

```json
{"fund_code": "110022", "month": "2026-10"}
```

响应骨架（**结构固定，插件只往 `results` 里加一个键**）：

```json
{
  "fund": {"code": "110022", "name": "..."},
  "month": "2026-10",
  "nav_series": [],
  "holdings": [],
  "results": {
    "returns.interval": {"status": "ready", "data": {}, "notes": []},
    "attribution.brinson": {"status": "stub", "data": {}, "notes": ["..."]}
  },
  "plugins": [],
  "errors": [],
  "meta": {"nav": {}, "holdings": {}}
}
```

`meta` 里必须保留数据来源信息：`source`、`cached`、`attempts`（降级记录）。

## 7. 契约变更规则

| 变更 | 是否兼容 | 流程 |
|---|---|---|
| 新增**可选**字段 | ✅ 兼容 | 直接 PR，无需审批口径 |
| 新增 `ctx.data` 的键 | ✅ 兼容 | PR + 在本文第 5 节登记 |
| 新增插件 | ✅ 兼容 | 无需改契约 |
| 新增**必填**字段 | ❌ 破坏 | 组长批准 + 改所有调用方 + 群里通知 |
| 改字段类型 / 单位 | ❌ 破坏 | 同上 |
| 删字段 / 重命名 | ❌ 破坏 | 同上 |
| 改 `nav` 的口径（如改用复权） | ❌ 破坏 | **必须新增字段**，见 4.2 |

破坏性变更的 PR 标题统一用 `feat(contract)!: ...`，并在 PR 里列出受影响的插件。

## 8. 并行开发不冲突的五个机制

| 机制 | 作用 |
|---|---|
| 类型只在 `engine/*/types.py` | 防止同名不同义 |
| 契约文件被 CODEOWNERS 锁定 | 改口径必须组长批 |
| 共享测试样本 `tests/fixtures/` | 所有人用同一份数据验证 |
| 契约测试 `test_contract.py` | 插件不符合契约直接红 |
| `ctx.data` 键登记 | 防止各自发明数据入口 |

## 9. 数据质量校验

已落地为 `engine/validation.py`，由 `api/routes/review.py` 在组装 `ctx.data` 之前调用。
插件拿到的数据已经过这层，**不需要自己写防御代码**。

| 校验 | 函数 | 规则 | 失败处理 |
|---|---|---|---|
| 净值合法性 | `clean_nav_series` | `nav > 0` 且可转数字 | 剔除该点并记 warning |
| 日期唯一且升序 | `clean_nav_series` | 无重复日期 | 保留首个并记 warning |
| 月份匹配 | `clean_nav_series(month=…)` | 至少两个有效点属于该月 | error，接口返回 404 |
| 权重范围 | `validate_holdings` | `0 ≤ weight ≤ 1` | error |
| 权重和 | `validate_holdings` | `Σweight ≤ 1 + 1e-6` | error |
| 残差空间 | `validate_holdings` | 权重和 < 0.999 | warning |
| 对账 | `validate_attribution` | 残差 < 0.001 | error |

用法：

```python
from engine.validation import clean_nav_series, validate_holdings, assert_valid

cleaned, report = clean_nav_series(raw_points, month="2026-10")
assert_valid(report)  # 严格模式：有 error 直接抛 ValidationError

holdings_report = validate_holdings(holdings)
if not holdings_report.ok:
    errors.extend(holdings_report.errors)
```

行为约定：

- **不修改输入**，清洗返回新对象
- **能修的修，不能修的报错**：净值异常点剔除并记 warning，权重越界记 error
- 持仓问题不阻塞主流程，但必须写进 `errors`，不允许静默

## 11. 已定口径（2026-11-18 定稿）

以下四项由组长拍板，全项目统一执行。

| 项 | 决定 | 落实方式 |
|---|---|---|
| 分红复权 | **默认做**（2026-11-18 修订） | `nav` 恒为单位净值；区间收益改用 `total_return_index`；结果 `notes` 标注「已做分红复权，基准日 X」 |
| 权重漂移 | **默认启用** | 归因类插件必须基于漂移后权重计算贡献度，并在 `notes` 写明漂移假设 |
| 行业分类 | **申万一级（2021 版）** | `HoldingPosition.industry` 只填申万一级行业名 |
| 对账容差 | **0.001（0.1%）** | `Σcontribution + residual_return` 与组合收益的差必须小于该值 |

落地配套：

- `tests/fixtures/` 真实数据样本，见该目录 README
- `engine/validation.py` 数据校验函数（已实现）
- 破坏性契约变更走 `feat(contract)!` 流程

### 11.1 2026-11-18 口径变更的影响

分红复权由「暂不做」改为「默认做」，属于破坏性变更，受影响范围：

| 受影响 | 变化 | 处理 |
|---|---|---|
| `returns.interval` 插件 | 区间收益改按复权口径，有分红的月份数值会变高 | 改读 `ctx.data["nav_total_return"]` |
| `tests/fixtures/expected.json` | 现有答案基于单位净值 | 重新生成样本时需一并抓取分红；当月无分红则答案不变 |
| 页面展示 | 收益数字可能比之前略高 | 卡片标注「已做分红复权」 |
| `ctx.data` | 新增 `nav_total_return` 键 | 已在第 5 节登记 |
