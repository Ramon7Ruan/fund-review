# 数据口径与契约（Data Contract）

> 目的：**让不同分支的代码能拼在一起跑**。
> 这份文件是全项目唯一的数据口径来源。代码里的类型定义以 `engine/*/types.py` 为准，
> 本文解释"为什么这么定"以及"什么能改、什么不能改"。
>
> 只想知道字段和数值怎么写，直接查 [`数据口径总表.md`](./数据口径总表.md)（表格速查版）。
>
> 状态：已定稿（2026-11-18）；组合分析补充 v0.5（2026-11-27）　关联：#1 数据接入、#2 归因引擎、#4 收益计算、#32 组合分析

---

## 0. 这份文件解决什么问题

八个人并行开发时，最容易出的不是 bug，而是**口径漂移**：

- A 把权重写成 `9.74`，B 按 `0.0974` 算，结果差 100 倍
- A 的"月收益"用自然月首尾，B 用 30 天滚动
- A 在插件里自己抓数据，B 从 `ctx.data` 取，同一只基金两个数

所以本文件先把**单位、时点、精度、缺失处理**定死，再定每个字段的含义。

## 1. 三条总原则

| 原则 | 含义 |
|---|---|
| **一个字段只有一个权威定义** | 类型只写在 `engine/*/types.py`，插件里不许重复定义同义结构 |
| **缺失不隐藏** | 拿不到的数据用 `null` 并写明原因，不许用 0 或前值填充 |
| **计算只在 engine** | 抓取在 `data_pipeline`，展示在 `web`，插件只做纯函数变换 |

## 2. 全局约定

### 2.1 单位与精度

| 项 | 约定 | 示例 |
|---|---|---|
| 比例（权重、收益率、回撤、贡献度） | **小数**，不是百分数 | `0.0974` 表示 9.74% |
| 金额 | 人民币**元** | `184489.91` |
| 数量 | 股 / 份 | `118.19`（万股，沿用数据源口径并标注） |
| 内部计算 | 不截断，用 float64 | — |
| 存储 | 比例保留 8 位小数 | `round(x, 8)` |
| 前端展示 | 比例 × 100 后保留 2 位，加 `%` | `3.98%` |

**前端负责格式化，后端只给小数。** 后端不许返回 `"3.98%"` 这种字符串。

### 2.2 日期与时间

| 项 | 约定 |
|---|---|
| 交易日 | ISO 字符串 `YYYY-MM-DD` |
| 月份 | `YYYY-MM` |
| 时区 | Asia/Shanghai，不存 UTC 时间戳 |
| 月度区间 | 该自然月内**第一个交易日 → 最后一个交易日**，不是 30 天滚动 |
| 数据时点 | 每个数据集带 `as_of`（该数据截至哪一天） |

### 2.3 命名

- 字段一律 **snake_case 英文**：`period_return`、`start_nav`
- 中文只用于展示字段：`title`、`name`、`note`
- 插件 id：点分小写 `模块.功能`，如 `attribution.brinson`
- 同义字段禁止另起名字：已有 `weight` 就不许再写 `ratio`、`position_pct`

### 2.4 缺失与异常

| 情况 | 处理 |
|---|---|
| 字段拿不到 | `null` + 在 `notes` 说明 |
| 整个数据集拿不到 | 该分区标 `error`，**其他分区照常返回** |
| 计算结果对不上 | 写进 `residual_return` 并披露，不许摊进已知项 |
| 数值非法（负净值、权重 > 1） | 抛 `ValueError`，由接口层转为错误信息 |

## 3. 数据分层与流向

```
L0 原始层    akshare 返回的 DataFrame（不落地、不跨模块传递）
   ↓ data_pipeline/sources/*
L1 标准层    统一为 dict/list，字段、单位、日期格式已归一   ← 唯一事实源
   ↓ DataService（缓存 + 降级）
L2 计算层    engine 的纯函数，输入 L1，输出结果类型
   ↓ api/routes/review.py
L3 展示层    /api/review 的 JSON，前端只读不改
```

**规则：L1 之后不允许再出现 pandas DataFrame。** 所有跨模块数据都是 dict/list/dataclass。

### 3.1 数据源优先级（2026-11-18 定）

产品的核心用法是「输入基金代码就看到分析」，所以**抓取是主路径，本地导入是兜底**：

```
当日缓存 → 抓取主源 → 抓取备源 → 本地已导入数据 → 报错
```

- 每一级都在 `meta.source` 标明来源，页面上可追溯
- 回退到本地导入时，必须同时给出 `as_of`，让用户知道数据截至哪天
- **抓取失败不等于没有数据**：宁可标注「本地数据，截至 X 月 X 日」，也不要静默返回空
- 导入数据日常不参与主路径，只在容灾、演示离线、用户自持完整持仓时使用

## 4. 核心实体字典

### 4.1 FundInfo —— 基金基本信息

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `code` | str | 是 | 6 位数字 |
| `name` | str | 是 | 基金全称 |
| `type` | str | 否 | 混合型 / 股票型 / 债券型 |
| `company` | str | 否 | 基金公司 |
| `cached` | bool | 是 | 是否命中缓存（调试用） |

### 4.2 NavPoint —— 净值点

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `date` | str | 是 | `YYYY-MM-DD`，交易日 |
| `nav` | float | 是 | **单位净值**，> 0，永远保留原始值 |
| `dividend_per_share` | float | 否 | 除息日每份现金分红，无分红记 0 |
| `total_return_index` | float | 否 | 红利再投资总回报指数，**以数据源首日为 1**（通常是基金成立附近），不是月初归一化 |

**`nav` 永远是单位净值，不复权。** 复权只通过 `total_return_index` 体现，
计算区间收益时用后者。这条是硬约束：任何人不得改变 `nav` 的含义。

> 注意 `total_return_index` 的基准日：它是从数据源最早一天累计下来的，
> 所以任意一个月的首日值通常不是 1（例如 2026-10-08 是 2.761）。
> 区间收益请用首末**比值**，不要把它的绝对值当净值展示。

### 4.3 HoldingPosition —— 持仓

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `code` | str | 是 | 6 位证券代码 |
| `name` | str | 是 | 证券名称 |
| `weight` | float | 是 | 占净值比例，**小数**，∈ [0, 1] |
| `industry` | str | 否 | 申万一级行业名，空串表示未映射 |
| `period_return` | float \| null | 否 | 该区间内个股收益，小数 |
| `quarter` | str | 是 | 披露期，如 `2026年1季度股票投资明细` |

**权重之和要求**：`Σweight ≤ 1`，差额即未披露部分，用残差项呈现。

### 4.3.1 HoldingChange —— 持仓变动（v0.4）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `code` | str | 是 | 6 位证券代码 |
| `name` | str | 是 | 证券名称 |
| `industry` | str | 否 | 申万一级行业；空串表示未映射 |
| `current_weight` | float | 是 | 本期权重，小数 |
| `previous_weight` | float | 是 | 上期权重，小数 |
| `delta` | float | 是 | `current_weight − previous_weight`，round 8 |
| `status` | str | 是 | `added` / `removed` / `increased` / `decreased` / `unchanged` |

**口径（硬约束）**：

- 两期**一律取前十大**后比较。季报条数不固定（可能 11–15 条），中报是全持仓；
  不统一口径会把上期非重仓持仓误判为「清仓」。
- `|delta| ≤ 1e-6` 记 `unchanged`，避免浮点噪声。
- 缺上一期时**不调用**变动计算，接口返回空数组 + `holdings_compare.note` 说明，不把全部持仓标为 `added`。
- 行业缺失保留空串，不猜。

### 4.4 DailyBar —— 个股日线（已接入，不复权）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `date` | str | 是 | 交易日 |
| `open/high/low/close` | float | 是 | 价格，元 |
| `volume` | float | 是 | 成交量，股 |
| `amount` | float | 是 | 成交额，元（量能异动用这个，不用 volume） |
| `turnover` | float | 否 | 换手率，小数 |

**复权口径**：v0.3 个股行情取数据源原始收盘价（`meta.quotes.adjust = "none"`）。
除权除息对个股贡献的影响由归因残差吸收，并在 `notes` 披露，不许假装已复权。

### 4.5 ContributionItem / AttributionResult —— 归因结果

沿用 `engine/attribution/types.py`。关键约束：

```
Σ(items.contribution) + residual_return ≈ 组合区间收益
容差：0.001（0.1%）
```

`residual_return` 必须显式存在，即使为 0。

v0.3 采用两层拆解（详见 [`归因口径.md`](./归因口径.md)）：

```
contribution   = weight × 个股区间收益
industry_part  = weight × 行业区间收益
selection_part = contribution − industry_part
```

两项之和恒等于贡献度；行业收益缺失时两者为 `null`，第一层仍可对账。
**不做标准 Brinson 三项**：缺少基准组合行业权重，硬算配置项等于编数字。

### 4.6 PortfolioReturn —— 组合收益（v0.2，v0.5 修订）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `month` | str | 是 | `YYYY-MM` |
| `status` | str | 否 | `ready` / `empty`；全部基金不可用时 `empty` |
| `total_return` | float | 是 | 组合区间收益，小数；只对 `available=true` 的项求和 |
| `contributions[]` | tuple | 是 | `{fund_code, weight, period_return, contribution, available}` |
| `cash_weight` | float | 是 | 现金权重，收益记 0 |
| `unavailable_weight` | float | 是 | 不可用基金权重和；无则 `0.0` |
| `residual_return` | float | 是 | 组合层恒为 `0.0`，保留字段以统一结构 |
| `notes[]` | tuple | 是 | 口径说明 |

**公式**：`R = Σ_available w_i × R_i + cash × 0 + residual`，其中 `residual = 0`。

**组合区间（关键）**：所有 `available=true` 的基金使用**共同首末交易日**计算 `period_return`；没有共同首末数据的基金按不可用处理。组合曲线与 `total_return` 必须使用同一组首末日期，否则 `I_last − 1 = total_return` 不成立。

**边界**：

- 权重和 `≤ 1 + 1e-6`，负数返回 400。
- 某基金无数据：`period_return = null`、`contribution = null`、`available = false`，权重计入 `unavailable_weight`，写 `errors`；**不重新归一**，避免悄悄改变组合定义。
- 全部基金不可用：`status = "empty"`、`total_return = 0.0`，前端按错误态展示，不显示为「收益为 0」。
- 月内持仓变动用分段加权；`compute_segmented_portfolio_return` **不在本次接口暴露**。

### 4.7 PortfolioInput —— 组合输入（v0.5 契约，待实现）

| 字段 | 类型 | 必填 | 约束 | 说明 |
|---|---|---|---|---|
| `month` | str | 是 | `YYYY-MM` | 回顾月份 |
| `weights` | dict[str, float] | 二选一 | 每项 `≥ 0`，和 `≤ 1` | 期初权重，小数 |
| `amounts` | dict[str, float] | 二选一 | 每项 `> 0`，单位元 | 期初投入金额 |
| `cash` | float | 否 | `≥ 0`，单位元 | 仅金额模式使用；缺省 0 |
| `include` | list[str] | 否 | `returns` / `curve` / `exposure` | 缺省 `["returns"]`；最小加载优先 |

**金额换算权重**（金额模式）：

```
total = Σ amounts + cash
w_i = amounts_i / total
cash_weight = cash / total
```

- 金额只用于换算权重，**不参与收益计算**；组合收益仍按 `R = Σ w_i × R_i`。
- 未提供 `cash` 时 `cash = 0`，权重自动归一为 1。
- 响应必须回显换算后的 `weights`，供用户核对。

**请求校验**（不满足返回 400，并给出具体原因）：

- 基金代码必须是 6 位数字；非法代码不进入抓取。
- `month` 必须是合法 `YYYY-MM`。
- 基金条目数 ≤ 20，防止大请求拖垮数据源。
- `weights` 与 `amounts` 同时出现返回 400。
- `amounts` 中金额为 0 的条目直接剔除；剔除后为空返回 400。
- `include` 含未知值返回 400；空数组等价于 `["returns"]`。
- 权重和允许 `≤ 1 + 1e-6` 的浮点容差。

### 4.8 PortfolioExposure —— 组合行业暴露（v0.5 契约，待实现）

| 字段 | 类型 | 说明 |
|---|---|---|
| `industries[]` | list | `{industry, weight}`，按 weight 降序；含「未映射」组 |
| `coverage` | float | 全部行业权重之和（**含未映射组**），相对组合总资产 |
| `uncovered` | float | 未覆盖的基金权重：债券、未披露持仓（**不含显式现金**） |
| `funds[]` | list | `{fund_code, weight, quarter, coverage}`，逐只披露期 |

> 恒等式：`coverage + uncovered = 1 − cash_weight`。显式现金只在 `cash_weight` 里，不重复计入 `uncovered`。

**公式**：`exposure_i = Σ_j w_j × industry_weight_j,i`。

- `w_j` 为基金 j 的期初权重，**不含现金**。
- `industry_weight_j,i` 来自基金 j 最近一期披露持仓；前十大之和 < 1 是正常的。
- 「未映射」作为 `industries[]` 中的一个分组参与汇总，不猜行业；其权重计入 `coverage`。
- 行业暴露**不做月内价格漂移**，保持披露时点权重。
- 各基金披露期可能不同，**逐只标注 `quarter`**，不合并成「同期」。
- 这是「披露持仓」口径，不是实时持仓；页面与报告必须标注。

### 4.9 PortfolioCurve —— 组合净值曲线（v0.5 契约，待实现）

| 字段 | 类型 | 说明 |
|---|---|---|
| `points[]` | list | `{date, index}`，`index` 为组合复权指数，首日 = 1 |
| `max_drawdown` | float | `min(index_t / peak_t − 1)` |
| `filled_days[]` | list | 因个别基金缺日而沿用前值的日期 |
| `start` / `end` | str | 实际使用的首末交易日 |

**合成**（与 `total_return` 使用同一组共同首末交易日）：

```
I_t = Σ_available w_i × (I_i,t / I_i,start) + Σ_unavailable w_i × 1
```

- 只使用复权总回报指数 `total_return_index`，不使用单位净值。
- 日期取各可用基金交易日的**并集**；某基金缺日沿用前一有效值，记入 `filled_days`。
- **前值填充只用于组合曲线的时间轴对齐**，不用于任何单基金收益计算，也不改变 `total_return`。
- 某基金连续缺 3 个交易日以上，按不可用处理，不再用前值硬撑曲线。
- 首日要求所有可用基金都有值；没有共同首末数据的基金按不可用处理。
- 不可用基金按水平线（指数恒为 1）参与，曲线与报告必须标注「该部分按不变处理」。
- 对齐后必须校验：`|I_last − 1 − total_return| ≤ 1e-8`，不通过视为算法错误。

沿用 `engine/screening/types.py`。

- `kind` 只能是 `price` / `volume` / `relative` / `industry`

## 6. 接口契约

### POST /api/review

请求：

```json
{"fund_code": "110022", "month": "2026-10"}
```

响应骨架（**结构固定，插件只往 `results` 里加一个键**）：

```json
{
  "fund": {"code": "110022", "name": "..."},
  "month": "2026-10",
  "nav_series": [],
  "holdings": [],
  "holdings_previous": [],
  "holdings_changes": [],
  "holdings_compare": {"note": "两期均按前 10 大截取后比较"},
  "results": {
    "returns.interval": {"status": "ready", "data": {}, "notes": []},
    "attribution.brinson": {"status": "stub", "data": {}, "notes": ["..."]}
  },
  "plugins": [],
  "errors": [],
  "meta": {"nav": {}, "holdings": {}}
}
```

`meta` 里必须保留数据来源信息：`source`、`cached`、`attempts`（降级记录）。

### POST /api/portfolio/review

> 以下是 v0.5 目标契约。当前实现只返回 `total_return / contributions / cash_weight / residual_return / notes / errors / meta`；`amounts`、`include`、`available`、`curve`、`exposure` 由 #34–#36 落地。新增字段全部为可选，不影响现有调用。

请求（权重模式）：

```json
{"month": "2026-10", "weights": {"110022": 0.4, "003095": 0.6}, "include": ["returns", "curve"]}
```

请求（金额模式）：

```json
{"month": "2026-10", "amounts": {"110022": 40000, "003095": 60000}, "cash": 0, "include": ["returns", "curve", "exposure"]}
```

响应骨架：

```json
{
  "month": "2026-10",
  "status": "ready",
  "weights": {"110022": 0.4, "003095": 0.4, "519674": 0.2},
  "total_return": -0.04399456,
  "contributions": [
    {"fund_code": "110022", "weight": 0.4, "period_return": 0.03984064, "contribution": 0.01593626, "available": true}
  ],
  "cash_weight": 0.0,
  "unavailable_weight": 0.0,
  "residual_return": 0.0,
  "notes": [],
  "errors": [],
  "meta": {"110022": {"name": "易方达消费行业", "type": "股票型-普通", "source": "akshare.eastmoney", "dividend_source": "eastmoney", "fallback": false}},
  "curve": {"points": [], "max_drawdown": -0.05, "filled_days": [], "start": "", "end": ""},
  "exposure": {"industries": [], "coverage": 0.0, "uncovered": 0.4, "funds": []}
}
```

字段说明：

| 字段 | 类型 | 何时返回 | 说明 |
|---|---|---|---|
| `status` | str | 总是 | `ready` / `empty` |
| `weights` | dict | 总是 | 回显实际使用的权重（金额模式为换算结果） |
| `total_return` | float | 总是 | 组合区间收益，只对 `available=true` 求和 |
| `contributions[]` | list | 总是 | `fund_code / weight / period_return / contribution / available` |
| `cash_weight` | float | 总是 | 用户显式现金权重，收益记 0 |
| `unavailable_weight` | float | 总是 | 不可用基金权重和，无则 0.0 |
| `residual_return` | float | 总是 | 组合层恒为 `0.0` |
| `notes[]` / `errors[]` | list | 总是 | 口径说明与失败原因 |
| `meta` | dict | 总是 | 逐只 `name / type / source / dividend_source / fallback` |
| `curve` | object | `include` 含 `curve` | `PortfolioCurve` |
| `exposure` | object | `include` 含 `exposure` | `PortfolioExposure` |

行为约定：

- 请求校验见 4.7；权重和 > 1、负数、非法代码、非法 `include` 均返回 400。
- 单只基金不可用：`period_return = null`、`contribution = null`、`available = false`，权重计入 `unavailable_weight`，写 `errors`，其余基金继续计算，HTTP 200。
- 全部基金不可用：`status = "empty"`、`total_return = 0.0`，前端按错误态展示，不显示为「收益为 0」。
- `contributions[].period_return` 与组合曲线使用**共同首末交易日**；没有共同首末的基金按不可用处理。
- `include` 只控制返回内容，不改变计算；默认 `["returns"]`，曲线与暴露显式请求。
- 现有字段语义不变，`status`、`weights`、`unavailable_weight`、`available`、`curve`、`exposure` 均为新增可选，向后兼容。

### 6.2 组合分析的数据复用与加载时间

> 以下是接口实现要求。当前实现已经复用 `DataService` 的净值缓存，但仍是串行抓取；并发与 `include` 按需返回由 #34 落地。

**复用优先**（不重复抓取）：

1. 组合接口不重新实现抓取，内部调用 `DataService.get_nav_adjusted`，与 `/api/review` 共用以下缓存键：
   - `nav:all:{code}`：净值序列（6 小时）
   - `dividends:{code}`：分红记录（7 天）
   - `holdings:{code}:{year}`：披露持仓（7 天，`exposure` 用）
   - `industry:map:v2`：个股 → 申万一级行业（7 天，`exposure` 用）

   单基金已抓过的，组合直接命中，不再访问数据源。
2. 组合接口不执行插件（不跑归因、不跑事件），只取净值与分红；`exposure` 才额外取持仓与行业映射，两者同样复用 `DataService` 缓存。
3. 前端只发一次 `/api/portfolio/review`，不逐只调用 `/api/review`；页面上已有单基金结果时不重复请求。
4. `include` 按需返回：默认只算收益（`["returns"]`），曲线与行业暴露作为后续阶段加载。

**并发与缓存一致性**：

- 多只基金净值抓取使用线程池（建议 4 并发），缓存命中直接返回；数据源限流时降级为串行或分批。
- 同一基金并发请求必须 single-flight：只发起一次抓取，其余请求等待结果，避免重复打源。
- 缓存写入需要加锁（尤其 SQLite），避免并发写坏缓存。
- 单只抓取失败重试一次并做指数退避，仍失败按「不可用」处理。
- 缓存过期且抓取失败时，允许降级使用过期缓存，但必须标 `stale: true` 与 `as_of`，不能伪装成新鲜数据。

**性能目标**（验收参考，不是硬性 SLA）：

| 场景 | 目标 |
|---|---|
| 缓存命中，5 只以内 | P95 ≤ 300ms |
| 冷启动，单只 | 10–25s |
| 冷启动，5 只并发 | ≤ 60s |
| `exposure` 持仓缓存命中 | < 500ms |
| `exposure` 冷启动 | ≤ 20s |

**准确性优先**：缓存过期时以新鲜数据为准，不用过期缓存凑数；任何降级都写 `notes` / `errors`，不静默。

**兼容声明**：

- 本接口不改变 `/api/review` 的任何字段与口径；组合收益是单基金复权收益的加权和。
- 组合层 `residual_return` 恒为 0，与单基金归因里的残差**不是同一概念**；不要把两者相加或对比。
- 组合行业暴露是「披露持仓」口径，与单基金归因的行业贡献不是同一指标。

已落地为 `engine/validation.py`，由 `api/routes/review.py` 在组装 `ctx.data` 之前调用。
插件拿到的数据已经过这层，**不需要自己写防御代码**。

| 校验 | 函数 | 规则 | 失败处理 |
|---|---|---|---|
| 净值合法性 | `clean_nav_series` | `nav > 0` 且可转数字 | 剔除该点并记 warning |
| 日期唯一且升序 | `clean_nav_series` | 无重复日期 | 保留首个并记 warning |
| 月份匹配 | `clean_nav_series(month=…)` | 至少两个有效点属于该月 | error，接口返回 404 |
| 权重范围 | `validate_holdings` | `0 ≤ weight ≤ 1` | error |
| 权重和 | `validate_holdings` | `Σweight ≤ 1 + 1e-6` | error |
| 残差空间 | `validate_holdings` | 权重和 < 0.999 | warning |
| 对账 | `validate_attribution` | 残差 < 0.001 | error |

用法：

```python
from engine.validation import clean_nav_series, validate_holdings, assert_valid

cleaned, report = clean_nav_series(raw_points, month="2026-10")
assert_valid(report)  # 严格模式：有 error 直接抛 ValidationError

if not holdings_report.ok:
    errors.extend(holdings_report.errors)
```

行为约定：

- **不修改输入**，清洗返回新对象
- **能修的修，不能修的报错**：净值异常点剔除并记 warning，权重越界记 error
- 持仓问题不阻塞主流程，但必须写进 `errors`，不允许静默

### 11.2 组合分析口径补充（v0.5，2026-11-27）

以下为新增内容，**不修改**第 11 节已定的单基金口径。

| 项 | 决定 | 落实方式 |
|---|---|---|
| 组合收益 | 单基金复权收益的加权和 | `R = Σ_available w_i × R_i`；不引入新的收益算法 |
| 组合残差 | **恒为 0** | 保留字段以统一结构；与单基金归因残差分开，不相加、不比较 |
| 组合区间 | **共同首末交易日** | 所有可用基金的收益与曲线使用同一首末，保证恒等校验 |
| 现金 | 收益记 0 | `cash_weight = 1 − Σw`；金额模式按总资产归一 |
| 不可用基金 | **缺失用 null，不记 0** | `period_return/contribution = null`、`available=false`，权重计入 `unavailable_weight`，不重新归一 |
| 组合曲线 | 复权指数加权，首日归一为 1 | 缺日沿用前值仅用于曲线对齐，不用于单基金收益；`I_last − 1` 必须等于 `total_return` |
| 行业暴露 | 披露持仓行业权重 × 基金权重 | 「未映射」作为分组参与汇总；逐只标注披露期；不等于实时持仓 |
| 加载策略 | 复用 `/api/review` 的净值缓存 | 组合接口不跑插件；并发抓取；`include` 默认 `["returns"]`，其余显式请求 |

**兼容性**：组合分析只读取现有数据与缓存，不改变 `nav`、`total_return_index`、持仓权重、归因字段的任何定义；单基金页面与报告不受影响。
