# 持仓快照与净值导入（Issue #1）

项目实际数据目录为 `data_pipeline/`。以下命令在仓库根目录运行；Windows 使用 `.venv\Scripts\python.exe`，Linux/macOS 使用 `.venv/bin/python`。运行数据存于 `data/cache/fund_review.db`，已被 `.gitignore` 排除。

## 持仓快照 CSV

UTF-8 编码，列名固定；`weight` 是占基金净值的小数，例如 9.74% 写成 `0.0974`。每行是**某基金在某个实际日期**的一只股票。要比较月初和月末，请分别提供两期快照；没有月末快照时系统返回 `null`，不会把当前持仓倒填到过去。

```csv
fund_code,as_of,stock_code,stock_name,weight
110022,2026-09-30,600519,贵州茅台,0.0974
110022,2026-10-30,600519,贵州茅台,0.0920
```

```text
python -m data_pipeline.import_data holdings data/raw/holdings.csv
python -m data_pipeline.import_data month 110022 2026-10
```

`month` 返回月初可用的最近快照与目标月内的最新快照，分别附原始 `as_of` 日期。它们是导入的真实时点数据，与基金季报披露持仓及算法推算权重区分使用。

## 基金净值 CSV 与自动拉取

`dividend_per_share` 为**除息日每份基金份额**派现金额；没有分红也必须写 `0`。数据库保留原始单位净值和分红，`adjusted-nav` 按需计算总回报指数。只导入一段历史时，指数从该段的首日锚定为 `1`。

```csv
fund_code,date,unit_nav,dividend_per_share
110022,2026-09-30,1.00,0
110022,2026-10-15,0.90,0.20
110022,2026-10-30,0.99,0
```

```text
python -m data_pipeline.import_data nav data/raw/nav.csv
python -m data_pipeline.import_data sync-nav 110022
python -m data_pipeline.import_data adjusted-nav 110022
```

自动拉取沿用 `DataService` 的净值主备源，并从东方财富分红页按基金代码和分红表标识核对除息事件；分红接口失败或除息日缺净值时直接报错，也可以用上述 CSV 手工导入。原始数据由 `data_pipeline/` 保存，`engine/returns/` 的纯函数按 `(当日单位净值 + 当日每份分红) / 前日单位净值` 逐日相乘，形成 `total_return_index`。上面的三点依次得到 `1.00 → 1.10 → 1.21`。示例数值仅用于演示公式，并非 110022 的真实分红。

同一期、同一内容再次导入会跳过；同日期不同权重、净值或分红会拒绝覆盖。整份 CSV 在一个事务中提交，任何冲突均回滚本次导入。个人持仓 CSV 与 SQLite 数据库均不提交到 GitHub。
