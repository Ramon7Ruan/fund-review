## 1. 这一步要解决的问题

组员的代码能力有限，而项目需要持续塞入新功能。因此本阶段**不追求功能数量**，只交付一个能长期承载新功能的骨架。

本阶段的成功标准只有一条：

> **组员新增一个功能，只需要新建文件，不需要修改任何已存在的文件。**

如果框架做不到这一点，后续每一次合并都要由组长手工调和，项目会在第二周失速。

主路径：

```

```

## 4. 核心设计：插件契约

### 4.1 为什么用自动发现而不是注册表

手册原方案是「在 `registry.ts` 加一行」。这仍然是**公共文件**，八个人同时改它必然冲突。

改为**目录自动发现**：新增功能 = 新建一个目录，零公共文件改动。这是本阶段最重要的技术决策。

| 方案 | 新增功能的改动面 | 冲突风险 |
|---|---|---|
| 手动注册表 | 新文件 + 修改 registry | 高，所有人改同一行区域 |
| **目录自动发现** | **只有新文件** | **无** |

### 4.2 后端插件契约

位置：`engine/plugins/<plugin_id>/plugin.py`

每个插件目录必须包含一个 `plugin.py`，导出名为 `PLUGIN` 的对象：

```python
PLUGIN = AlgorithmPlugin(
    id="attribution.brinson",  # 全局唯一，点分命名空间
    title="Brinson 归因",
    version="0.1.0",
    status="stub",  # stub | ready
    inputs=PositionSeries,  # 输入契约（类型）
    outputs=AttributionResult,  # 输出契约（类型）
    run=run,  # 纯函数：不碰网络、不碰数据库
)
```

运行时职责（框架提供，组员不写）：

- 启动时扫描 `engine/plugins/*/plugin.py`
- 导入失败的插件标记为 `unavailable`，**不影响其他插件与整个应用启动**
- 记录加载日志：成功、失败原因、耗时
- 暴露 `GET /api/plugins` 调试端点，列出全部插件状态

### 4.3 前端插件契约

位置：`web/src/features/<feature_id>/`

```
web/src/features/<feature_id>/
  manifest.ts     # id、title、order、status、对应后端插件 id
  Panel.tsx       # 默认导出的卡片组件
```

框架用 `import.meta.glob` 收集所有 `manifest.ts`，自动生成卡片与路由。**组员不需要碰路由文件、菜单文件或任何公共组件。**

### 4.4 占位状态是一等公民

`status: "stub"` 的插件在前端显示统一的占位卡：

- 卡片标题与一句话说明
- 「待接入」标签
- 该插件的输入输出契约摘要（让组员知道要实现什么）

**占位卡不允许报错、不允许空白**。页面在只有 stub 插件时也必须完整可用。

### 4.5 可逆性要求

删除任意一个插件目录后，应用必须仍能正常启动和渲染，只是少一张卡片。这一条用于证明插件之间没有隐式耦合。

## 5. 核心算法的位置与契约

本阶段只固定**位置与接口**，不实现算法。

| 包 | 职责 | 输入 | 输出 | 本阶段状态 |
|---|---|---|---|---|
| `engine/returns/` | 区间收益、组合收益、权重漂移 | 净值序列、持仓快照 | `ReturnSeries` | 实现区间收益（简单），权重漂移留 stub |
| `engine/attribution/` | 个股贡献度、行业拆解、Brinson | 权重序列、个股行情 | `AttributionResult` | 全部 stub |
| `engine/screening/` | 异动检测（价格/量能/相对/行业） | 行情序列、阈值配置 | `Anomaly[]` | 全部 stub |

每个包下必须包含：

- `types.py`：该包的输入输出数据类型
- `_template.py`：可复制样板，含签名与返回结构
- `test_contract.py`：契约测试——验证占位实现按约定抛出 `NotImplementedError`，且类型定义可实例化

**契约测试是本阶段的交付物之一**，它保证后续组员实现算法时有明确的验收靶子。

### 6.3 必须实现的交互状态

| 状态 | 表现 |
|---|---|
| 空输入 | 按钮禁用，提示输入 6 位基金代码 |
| 代码格式错误 | 内联提示，不发起请求 |
| 抓取中 | 分阶段进度文案，按钮 loading，禁止重复提交 |
| 数据源失败 | 显示失败源与已切换的备用源，页面其他部分仍可用 |
| 基金不存在 | 明确提示，不显示空白卡片 |
| 成功 | 净值曲线 + 占位卡完整渲染 |

## 7. 接口契约（草案）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/health` | 存活检查，CI 与本地联调用 |
| GET | `/api/plugins` | 插件清单与状态，含失败原因 |
| GET | `/api/funds/{code}` | 基金基本信息 |
| POST | `/api/review` | 入参 `{fund_code, month}`，返回月度回顾聚合结果 |

`/api/review` 返回结构按插件 id 分区：

```json
{
  "fund": {"code": "110022", "name": "易方达消费行业"},
  "month": "2026-10",
  "nav_series": [{"date": "2026-10-09", "nav": 2.986}],
  "results": {
    "attribution.brinson": {"status": "stub"},
    "screening.anomaly": {"status": "stub"}
  },
  "errors": []
}
```

**新增插件只在 `results` 里增加一个键，不改变整体结构**。这是前后端能并行开发的前提。

## 8. 工程基座

| 命令 | 作用 | 验收 |
|---|---|---|
| `make setup` | 安装 Python 与前端依赖 | 新克隆的机器上一次跑通 |
| `make dev` | 同时启动后端与前端 | 浏览器可打开工作台 |
| `make check` | 类型检查 + 全部测试 + 前端构建 | 全绿才能提 PR |

CI 两个 job 并行：`backend`（ruff + pytest）、`frontend`（tsc + vitest + build）。

## 9. 验收标准（Definition of Done）

| 编号 | 标准 | 验证方式 |
|---|---|---|
| AC1 | **新增一个示例功能，只新增文件，不修改任何已存在文件** | `git diff --name-only` 只显示新增路径 |
| AC2 | 删除示例插件目录后应用正常启动，页面少一张卡 | 手动验证 |
| AC3 | 输入 `110022` + `2026-10`，页面出现真实净值曲线 | 手动验证，数据与天天基金一致 |
| AC4 | 三个算法包的契约测试通过，占位实现按约定抛 `NotImplementedError` | `pytest` |
| AC5 | 新克隆仓库，`make setup && make dev` 可运行 | 在干净目录验证 |
| AC6 | `make check` 全绿，CI 两个 job 通过 | CI 记录 |
| AC7 | 任意单个插件抛异常，不影响其他插件与页面 | 故障注入测试 |

AC1 与 AC7 是本阶段的核心，其余是常规质量门槛。

## 10. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 自动发现对新手不透明，「为什么我加了文件没出现」 | 组员频繁求助 | `/plugins` 调试页 + 启动日志打印加载清单 + 示例插件文档 |
| 东财接口在本机不可用 | 净值曲线拿不到数据 | 数据层必须实现备用源，实测结论见项目说明第六节 |
| 占位契约设计不当，后期返工 | 算法接入时改接口 | 契约先评审再写代码，评审通过才进入 T4 |
| 组员直接改框架文件 | 插件机制被绕过 | CODEOWNERS 已覆盖全仓库，配合 PR 检查改动路径 |
