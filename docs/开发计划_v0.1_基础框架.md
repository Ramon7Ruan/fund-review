## 1. 技术清单

| 项 | 选择 | 理由 |
|---|---|---|
| Python | 3.11+，运行时与开发依赖分别声明在 `requirements*.txt`，安装统一走 `requirements-lock.txt` 锁定版本 | 本机与 CI 版本一致 |
| 后端 | FastAPI + uvicorn | 自动 OpenAPI，前后端不用口头约定 |
| 数据 | `akshare` 抓取、`pandas` 处理、SQLite 缓存 | 本地零运维 |
| 前端 | React 18 + TypeScript + Vite | 插件自动发现依赖 Vite 的 `import.meta.glob` |
| 样式 | Tailwind CSS | 卡片式界面，组员不用写复杂 CSS |
| 图表 | ECharts | 净值曲线、后续瀑布图都有现成方案 |
| 测试 | pytest、vitest、Testing Library | 后端与前端各自独立 |
| 质量 | ruff（Python）、tsc（TS）、`make check` 统一入口 | 组员只需会跑一条命令 |

不引入 Redux、不引入 ORM、不引入 Docker。本阶段它们只增加组员的理解成本。

## 2. 目标目录结构

```
fund-review/
├── Makefile
├── pyproject.toml              # ruff / pytest 配置
├── requirements.txt            # Python 运行时依赖
├── requirements-dev.txt        # 测试与 lint 依赖
├── .github/workflows/ci.yml
│
├── engine/                     # 纯计算，不碰网络与数据库
│   ├── runtime/
│   │   ├── plugin.py           # AlgorithmPlugin 协议与类型
│   │   ├── loader.py           # 目录自动发现 + 错误隔离
│   │   └── errors.py
│   ├── returns/                # 区间收益、权重漂移
│   ├── attribution/            # 贡献度、行业拆解（stub）
│   ├── screening/              # 异动检测（stub）
│   └── plugins/                # 组员算法插件，一人一目录
│       └── _example/
│
├── data_pipeline/              # 抓取、清洗、缓存
│   ├── sources/                # akshare 适配器，一类数据一个文件
│   ├── cache/                  # 缓存抽象 + SQLite 实现
│   └── fallback.py             # 主源失败 → 备用源
│
├── api/
│   ├── app.py                  # FastAPI 实例、中间件、异常处理
│   ├── routes/                 # health / funds / review / plugins
│   └── schemas.py              # 响应模型
│
├── web/
│   ├── package.json            # 前端依赖与脚本（make 是唯一入口）
│   └── src/
│       ├── core/               # 布局、请求封装、插件收集器
│       ├── components/         # 通用卡片、加载态、错误态
│       ├── features/           # 组员视图插件，一人一目录
│       │   ├── fund-overview/
│       │   ├── nav-chart/
│       │   └── _example/
│       └── pages/              # 工作台、插件调试页
│
└── tests/                      # 后端测试（CODEOWNERS 锁定）
```

**组员只允许在 `engine/plugins/<自己的名字>/` 和 `web/src/features/<自己的名字>/` 下新建目录。** 其余路径的改动都需要组长批准。

## 3. 任务拆解

估时以一人为主力，单位为人日。T 编号即分支与提交信息的依据。

### T0 工程基座　0.5 人日　无依赖

| 项 | 内容 |
|---|---|
| 产出 | `Makefile`、`pyproject.toml`、`package.json`、`.gitignore` 补充、目录骨架 |
| 验收 | `make setup` 在干净克隆中跑通；`make check` 能执行（允许空测试通过） |
| 测试 | `make check` 自身可运行 |

### T1 后端骨架　0.5 人日　依赖 T0

| 项 | 内容 |
|---|---|
| 产出 | `api/app.py`、配置加载、统一错误格式、`GET /api/health`、CORS |
| 验收 | `uvicorn` 启动后 `/api/health` 返回 200；错误响应结构统一 |
| 测试 | health 集成测试；未捕获异常被转为统一错误结构的测试 |

### T2 插件运行时　1.0 人日　依赖 T1　**本阶段核心**

| 项 | 内容 |
|---|---|
| 产出 | `engine/runtime/plugin.py`、`loader.py`、插件状态模型 |
| 验收 | 新建插件目录即被加载；导入失败标记 `unavailable`；删除目录后正常启动 |
| 测试 | 自动发现、重复 id 拒绝、导入异常隔离、运行异常隔离、可逆性（删除后重启） |

**决策点**：T2 完成后先评审插件契约，再继续。契约错了后面全部返工。

### T3 数据层　1.0 人日　依赖 T0，可与 T2 并行

| 项 | 内容 |
|---|---|
| 产出 | `data_pipeline/sources/`（基金净值、基金持仓、个股日线、行业指数）、缓存抽象 + SQLite 实现、备用源切换 |
| 验收 | 基金净值主源失败时自动切备用源并记录；相同参数二次调用命中缓存 |
| 测试 | 缓存读写、TTL 过期、主源失败切换（mock，不依赖真实网络）、字段标准化快照 |

**网络测试一律用录制样本**，CI 不访问外网。真实接口只在本机手动验证。

### T4 核心算法契约　0.5 人日　依赖 T2

| 项 | 内容 |
|---|---|
| 产出 | `returns/`、`attribution/`、`screening/` 三个包的 `types.py`、`_template.py`、占位实现 |
| 验收 | 区间收益可计算；其余按契约抛 `NotImplementedError`；类型可实例化 |
| 测试 | 区间收益已知答案用例；占位实现的契约测试；权重漂移的输入输出类型测试 |

### T5 API 聚合层　0.5 人日　依赖 T2、T3、T4

| 项 | 内容 |
|---|---|
| 产出 | `GET /api/funds/{code}`、`POST /api/review`、`GET /api/plugins` |
| 验收 | `/api/review` 返回 `results` 按插件 id 分区；某插件失败只影响自己的分区 |
| 测试 | 响应结构快照、插件失败隔离、基金不存在的错误路径 |

### T6 前端骨架　0.5 人日　依赖 T0，与后端并行

| 项 | 内容 |
|---|---|
| 产出 | Vite + React + TS + Tailwind、路由、布局、请求封装、代理到后端 |
| 验收 | 页面可打开，能调通 `/api/health` |
| 测试 | 应用渲染 smoke test |

### T7 前端插件机制　0.75 人日　依赖 T6　**本阶段核心**

| 项 | 内容 |
|---|---|
| 产出 | `import.meta.glob` 收集器、`manifest.ts` 类型、通用卡片容器、stub 占位卡 |
| 验收 | 新增 feature 目录即出现新卡片；stub 状态显示契约说明；不出现空白 |
| 测试 | manifest 收集、stub 渲染、插件组件抛错时的错误边界 |

### T8 月度回顾工作台　1.0 人日　依赖 T5、T7

| 项 | 内容 |
|---|---|
| 产出 | 输入区（基金代码、月份）、加载态、基金概览卡、净值曲线、三个 stub 卡、`/plugins` 调试页 |
| 验收 | PRD 第 6.3 节全部六种交互状态符合预期 |

### T9 CI 与质量门禁　0.75 人日　依赖 T0，最后联调

| 项 | 内容 |
|---|---|

## 5. 提交策略

| PR | 包含 | 说明 |
|---|---|---|
| PR-1 | T0、T1、T9 | 工程基座与 CI，让后续 PR 有门禁 |
| PR-2 | T2、T3、T4、T5 | 后端插件运行时与数据层 |
| PR-3 | T6、T7、T8 | 前端工作台 |
| PR-4 | T10 | 示例插件与上手指南，组员从此开始接手 |

骨架阶段单个 PR 的改动行数会超过手册的 400 行上限，属于**一次性例外**，在 PR 描述中注明。T10 之后组员提交仍严格按 400 行执行。

## 6. 测试策略

| 层 | 测什么 | 不测什么 |
|---|---|---|
| 单元 | 插件加载、缓存、备用源切换、收益计算、契约 | 不访问真实网络 |
| 集成 | `/api/health`、`/api/review` 聚合与失败隔离 | 不测第三方接口稳定性 |
| 前端 | manifest 收集、stub 渲染、交互状态、错误边界 | 不做像素级视觉回归 |
| 端到端 | 扩展性验收脚本、故障注入 | 不做多浏览器矩阵 |

**CI 全程不访问外网**，所有第三方数据用录制样本。真实接口只在本机 `make probe` 手动验证，避免 CI 因数据源波动而随机失败。

| 阶段 | 内容 | 估时 |
|---|---|---|
| 第 1 段 | T0、T1、T9 | 1 天 |
| 第 2 段 | T2、T3、T4、T5，含契约评审 | 2 天 |

## 8. 风险与回滚

| 风险 | 触发信号 | 回滚方式 |
|---|---|---|
| 插件契约设计不当 | T4 时发现类型无法表达算法输入输出 | 停在 T2 重新评审，不带着错契约往下写 |
| 前端自动发现在构建时失效 | 生产构建后插件缺失 | 保留显式注册作为降级方案，仅组长可改 |
| CI 因外网不稳定随机失败 | 同一提交反复红绿 | 立即移除网络测试，改用录制样本 |
| 组员在 T10 之前就开始改框架 | PR 出现核心路径改动 | 打回并指向 `_example` 目录 |

## 9. 完成后的状态

- 组员拿到的是「复制一个目录、改一个函数、刷新页面」的工作方式
- 组长的合并工作从「读懂每行代码」变成「看 CI + 看改动路径」
- 归因、异动、报告导出都有明确的接入位置，后续按 `docs/项目说明.md` 的 v0.2 / v0.3 推进
