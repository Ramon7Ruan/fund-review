# fund-review

投后月度回顾工具。面向个人投资者，输入持仓与净值数据，输出月度投资回顾报告与基金涨跌归因。

## 核心功能

- 导入持仓快照与基金净值数据
- 计算区间收益（含分红复权）
- 对基金涨跌做归因拆解（行业、风格、个股选择）
- 生成可导出的月度回顾报告

## 当前进度

**已交付（tag `v0`）**：插件自动发现机制、数据抓取与缓存、月度回顾工作台、真实净值曲线、区间收益、CI 双 job。

**v0.2**：数据口径与契约、数据校验层、分红复权、组合收益（含分段加权）。

**v0.3**：归因引擎（持仓贡献、行业拆解、行业/个股两层拆分、残差对账）与相关事件陈列
（可溯源 + 直接相关 + 时间可确认 + 去重四条准入，不做因果判断、不给建议）。
口径见 [`docs/归因口径.md`](docs/归因口径.md)。

**尚未实现**：Brinson 三项（需先接入基准行业权重）、异动检测、报告导出。

## 新人第一步

克隆仓库后，先装防误推的钩子：

```bash
bash scripts/install-hooks.sh
```

装完直接推 `main` 会被本地拦截。

服务端也已启用分支保护（`protect-main` 规则集）：禁止删除 `main`、禁止强推、只允许 squash 合并、CI 必须全绿。**核心代码、测试与基建必须由组长 approve**；插件目录的新功能只需任意 1 人 approve 即可合并。本地钩子只是提前一步拦住手滑，真正决定改动能否进主干的是 GitHub 那边。

组长（仓库管理员）留了紧急绕过通道，仅用于主干坏掉必须立刻修的情况，事后要在群里说明。

## 本地运行

需要 Python 3.11+ 与 Node 20+。装了 [`uv`](https://docs.astral.sh/uv/) 会更快；没装也能用，`make setup` 会自动回退到 `venv` + `pip`。

后端依赖版本已锁定在 `requirements-lock.txt`，本机与 CI 装到同一版本，不会出现"我这能跑、你那报错"。

```bash
make setup     # 安装后端与前端依赖（首次）
make dev       # 同时启动后端 8000 与前端 5173
```

打开 http://localhost:5173 ，输入基金代码（如 110022）与月份即可生成月度回顾。

真实数据抓取需要额外安装 akshare，**版本不得低于 1.20.65**（个股公告接口依赖该版本的参数签名；更低版本会在抓取公告时给出明确的升级提示）：

```bash
# 有 uv 时
uv pip install --python .venv/bin/python "akshare>=1.20.65"
# 没有 uv 时
.venv/bin/python -m pip install "akshare>=1.20.65"
```

也可以直接安装可选依赖清单：

```bash
.venv/bin/python -m pip install -r requirements-akshare.txt
```

其他命令：

| 命令 | 作用 |
|---|---|
| `make check` | 类型检查 + 全部测试 + 前端构建，提 PR 前必跑 |
| `make backend` | 只启动后端 |
| `make frontend` | 只启动前端 |
| `make test` | 只跑测试 |

## 目录结构

```
engine/         纯计算：收益、归因、异动，不碰网络与数据库
engine/plugins/ 算法插件，一人一目录，自动发现
data_pipeline/  抓取、缓存、备用源切换
api/            FastAPI 接口
web/src/features/ 前端视图插件，一人一目录，自动发现
tests/          后端测试
```


## 协作方式

先读 [`docs/小组协作手册.md`](docs/小组协作手册.md)。里面写了分支规范、任务卡模板、PR 规矩、以及怎么给框架加一个新功能。

要动手写第一个功能，直接照 [`docs/如何新增一个功能.md`](docs/如何新增一个功能.md) 做：复制两个示例目录、改三处名字、写一个函数，不需要改任何已存在的文件。

三条底线：

1. 不直接推 `main`，一切走 PR
2. 不改别人的模块目录不打招呼
3. 归因算法不过对账测试，不算完成
